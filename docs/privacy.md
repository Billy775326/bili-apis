# 公开仓库的数据边界

Git 仓库及 GitHub 禁止包含真实账号或联系人标识、消息 key/序号/正文、上传及收藏等测试资源标识、Cookie、Token、密码、个人路径和未脱敏响应。真实公开资源样本也不例外。接口域名/路径、字段名、技术枚举、源码与制品哈希、来源偏移、状态码、测试断言及时间保留，用于解释协议和验证结果。

本地被 Git 忽略的 `.local` 运行资料不属于公开产物；不得通过复制文件、暂存调试日志或截图将其带入提交。测试向量和调用示例使用明确标注的合成数据。

## 发布验证证据

1. 使用本地授权输入运行真实请求和字段断言。
2. 断言完成后再调用 `sanitizePublicEvidence`，省略 `public_input` 的全部值、URL 查询值、账号/直播间路径及页面标题。
3. 公开 `[REDACTED_INPUT]` 等标记、参数名、原响应哈希及断言结果。标记不是向服务器发送的实际输入，不能照抄执行。
4. SDK 示例保留合成占位值；真实用户及直播资源由调用者显式提供，不在验证脚本中预置真实账号。

状态码、成功/失败和断言均不因脱敏而调整。查询值省略后，仍保留请求参数名；公开材料不再提供直接复用原始样本的条件。

## 检查命令

```sh
npm test
npm run privacy:check
```

CI 对所有受版本控制文件运行检查，压缩 JSON 先解压再扫描。规则覆盖未脱敏运行记录、非合成 BV 标识、个人绝对路径和凭据字面量；明确标注的合成安全测试向量仅在 tests 目录允许。

本机还可以提供一份被忽略的私有值列表，检查真实运行数据是否混入任何跟踪文件；检查器只输出文件和规则，不打印命中的真实值：

```sh
node scripts/check-public-data.mjs --private-values .local/privacy-audit/runtime-values.json
```

自动规则无法识别所有可能的个人信息，提交前仍需审核差异、新增文件和脱敏上下文。不要将会话、真实正文或完整响应交给检查日志。

## Git 历史

普通删除或脱敏提交不会移除旧提交中的数据。历史审计和历史清理分别记录：先准备受影响引用、提交映射及清理预览，再按仓库所有者授权决定是否替换共享历史。未经明确授权不强推、删除共享分支或移动标签；也不把本地预览称为 GitHub 历史已清理。
