目标是逐条验证固定版本 Play APK 中的 2,325 条 HTTP 声明和 604 条 gRPC 路由。资源/native 线索尚未确认为接口的，继续保留候选状态。GET 也可能发送短信或改变状态；POST 和 gRPC 也可能只是查询，需要按具体操作审核。

用户暂时无法登录，当前只推进匿名验证。普通测试账号可在后续由用户自行登录。实体手机不属于当前测试目标。原安装包、完整流量、会话、XML 和截图保留在忽略目录；设备序列号和连接地址不进入提交。

## 第一批可审阅的验证范围

设备与账号就绪后，先采集并核对匿名与已登录的详情、搜索、分区、公开空间、评论读取、收藏列表和直播状态请求。逐个比对 App 实际使用的路径、参数、拦截器、返回字段及错误语义；gRPC 先从已核对的 View/View 及搜索、评论读取开始。

之后才将可复现的只读场景扩展为受限速、超时、取消和停止条件控制的执行计划。参数未知、动态 URL 未恢复、流式语义未确认或操作副作用未审核的条目保持待处理，不批量填入猜测值调用。

涉及私信和个人历史的正文不保存到仓库。只记录脱敏场景 ID、断言结果、来源版本、时间和必要的结构摘要。账号和会话数据保留在设备或忽略目录中，不通过 GitHub Actions Secrets 或聊天传递。

## 写操作需要的具体范围

尚未获得具体对象与操作范围，以下项目只列需求，不执行：

- 点赞、收藏、关注及撤销：需要测试账号、对象 ID、次数上限和撤销范围。
- 评论、动态、私信：需要自有对象或同意接收的测试账号、测试文本、次数和后续清理规则。
- 投稿或上传：需要无隐私的专用媒体、测试草稿和是否允许公开发布的选择。
- 删除：仅能在范围明确时清理本次创建的测试对象；删除原有内容另行明确。
- 支付、充值、购买、送礼、投币或其他余额消耗：需要具体预算、商品/对象、次数及可用测试环境；已有“全量验证”目标不提供这些操作的默认预算。

已有项目约定要求“真实私信、发布、关注等有外部影响的测试，需要明确授权”。上述范围尚无具体对象和数量，后续会提交可审阅的执行计划再申请对应授权。

## 验收证据

成功需满足场景中的业务返回和相关字段/状态断言；HTTP 200、接口字符串存在、离线测试通过都不能替代。认证错误、参数错误、网络失败、客户端未触发、权限不足和暂未验证分别记录。分页、流式事件、写入结果和清理结果按接口性质补充。

全量报告展示每个声明的结论与未覆盖原因；不把缺少权限、已下线或不能在当前设备触发的声明伪装成验证成功。
